# 诉求理解与流程选择

本方法用于处理方式发生变化或存在多个目标的时候。问题已经明确时直接进入对应业务 Skill，不增加单独的分类步骤。

## 选择与切换

| 用户当前目标 | 处理方式 |
| --- | --- |
| 了解功能、规则、权限或操作 | `faq-support` |
| 预期能完成但实际失败 | `issue-support` |
| 明确希望新增、改进能力或记录建议 | `requirement-support` |
| 补充事实或反馈验证结果 | 更新当前问题；等待人工或人工处理中不自动重启排查 |

按真实目标和现象判断，不靠关键词。“找不到入口”可能是权限、操作或异常；“希望更好用”不自动成为保存请求。

多诉求同时出现时，优先处理用户指定的事项；未指定时先处理阻塞当前使用的问题，保留其余诉求。不要因为切换 Skill 而忘记尚未处理的建议，也不要擅自写入。

切换时带上仍适用的目标、环境、事实和尝试结果。用户更正角色、版本或终端时，先替换旧事实，再重新核对受影响的判断；不要求重新提供整套信息。

用户开始新问题时，重新判断旧环境是否仍适用。各事项分别跟踪完成状态：建议保存、问题恢复和知识审核是不同的结果。

先检查当前事项是否已交给群内人工，再决定是否继续路由。明确找人工的请求按总控规则立即处理；重新请助手协助或独立的新问题可以重新选择 Skill，不能顺带重开仍由人工处理的事项。

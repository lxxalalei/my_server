# 知识检索与证据核对

为当前问题寻找足够可靠的依据；不负责替用户决定是否保存建议或审核案例。

**产品事实回答的门槛是：已经成功读到支持该事实的正文。** 未达到门槛时，功能是否存在、权限和操作步骤都保持无法确认。索引、标题、manifest 或摘要中出现某个主题，只能证明有这个资料条目；不能据此说功能存在、暗示支持，也不能说功能不存在。不要在“无法确认”前后再补一个未经正文支持的肯定结论。

## 确定查询

从用户目标或症状提取主题、环境和待核实事实。将口语映射为候选关键词，但不把关键词映射当成诊断结论。先找少量相关文件，再读正文；已有会话证据仍适用时复用。

功能、权限和入口优先查产品规则；异常先核对规则，再查案例。根据已取得的结果换同义词或主题词；新检索不能增加信息时停止，不循环搜索。

## 读取与适用性

搜索结果只帮助定位。依赖具体事实回答前，实际读取正文，并确认：

- 来源与读取是否成功，而不只是看见标题或摘要。
- 版本、终端、角色和条件是否匹配当前问题。
- 产品规则与案例各自支持什么；案例的成功不能变成普遍保证。
- 正文是否确实回答所问事实；未覆盖的内容保留未知。

资料冲突时比较适用范围和来源；无法消除的冲突明确保留，不挑选方便的答案。撤回、待审和驳回案例不能作为在线已审核知识。

## 失败处理

- 零命中：可以有限度换关键词；仍无依据时说明当前资料无法确认。
- 读取失败：保留工具错误与未取得正文的事实，不能说成功查过，也不能据此断言功能不存在。
- 可恢复的本地缓存问题：按工具契约修复后重新读取，只有成功读到正文才恢复事实回答。
- 权限不足或工具不可用：不猜测隐藏接口、不绕过权限，说明缺少的依据。需要时提供已有事实摘要。

对外只给结论、必要适用范围和可执行下一步；用户需要核对时提供真实来源。无需输出内部检索表单。

## 工具适配

使用 `tools/support.py` 查询知识库，命令和返回字段见[工具说明](../../../docs/tools.md)。知识来源由仓库根目录的 `knowledge-source.json` 指定；尚未同步或需要更新资料时执行 `sync`，之后通过 `search` 定位、`read` 读取正文。

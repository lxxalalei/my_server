# Knowledge Search｜知识检索 v0.1

## 目标与边界

帮助主客服 Agent **找到可核实、适用于当前场景的资料**，而不是替主 Agent 决定所有对话流程。对外回复由主 Agent 负责。

本 Skill 只定义检索方法，不自带网络/CLI 权限，不自动连接 OpenViking，不写入知识库，不提交工单。只有实际暴露的读取/搜索工具才能执行检索。

## 何时使用

- 用户问产品功能、操作步骤、权限限制、平台差异等**依赖产品事实**的问题。
- 用户反馈异常，需要定位已知问题、相关规则或可验证的排查方案。
- 用户表达“产品是不是不支持”“为何找不到入口”等，必须先核对现有功能再判断。
- 多轮对话中出现新的现象、终端、版本或排查结果，使之前的依据可能不再适用。

不必每轮都重复检索：如果当前会话已获取且仍然适用的资料足够，就直接沿用。简单寒暄、纯粹的澄清问题不需要检索。

## 知识来源与适配

### 开发演示模式

使用公开的 [lxxalalei/knowledge](https://github.com/lxxalalei/knowledge) 作为**模拟知识库**。

1. 先读 [知识目录](https://github.com/lxxalalei/knowledge/blob/main/README.md)，或使用已连接的仓库搜索定位候选文件。
2. 阅读匹配文档的**正文**，必要时顺着文档中的关联链接读取另一篇文档。
3. 记录准确的源文件路径与链接，例如 `product/group-chat.md`、`cases/image-send-failure.md`。
4. 文档均为 **DEMO 虚构资料**。模拟问答要明确使用“演示版”语境，**不能作为真实火星 IM 的产品事实**。

如果当前运行环境没有 GitHub 访问/文件读取能力，不能假装已读仓库；只能根据明确提供的文档内容回答或说明尚缺检索工具。

### 公司正式模式（适配目标，尚未接入）

- **KMS CLI**：搜索、读取 Markdown 产品文档、操作说明、权限与业务规则。优先作为正式产品事实来源。
- **在线表格 CLI**：查询有结构化字段的已知问题、适用版本、处理状态、方案链接等。区分“已确认解决”“处理中”“未核实”。
- **OpenViking**：只有在公司平台确实提供且授权使用时，作为补充索引/历史经验检索，不能用未经核实的历史内容覆盖 KMS 官方规则。

以上是**能力类型**，不是已经存在的具体命令名。对接时必须读取实际 CLI 规范，确认搜索、读取、权限与结果字段后才能调用。不要编造 `kms.search` 等命令。

## 操作方法

### 第 1 步：提炼检索目标

根据当前对话提取：
- **用户目标/现象**：想做什么、预期是什么、实际发生什么。
- **已知约束**：终端、版本、群聊/消息/会议等功能模块、已尝试且无效的步骤。
- **待核实的事实**：某功能的入口、权限、限制，或某异常是否已有确认方案。

将口语化症状映射到可能的文档用语，例如“发图一直转圈”可检索“图片发送失败、发送中、上传限制”；不把映射后的词当作已确认原因。

### 第 2 步：选择来源并查找

- 功能、操作、权限类 → 优先产品规则与操作文档。
- 使用异常 → 先查相关产品规则/约束，再根据线索查已知问题与案例。
- 版本、修复状态类 → 需要带版本和状态的最新记录；没有对应数据就不能确认。
- 首轮结果不足时，可换同义词或具体症状补查；不要反复进行没有新信息的同一检索。

原则上先定位少量高相关文档，再读正文，不批量读取整个仓库来增加上下文。

### 第 3 步：核对证据

回答前逐一确认：
1. **是否真正读到正文**：只有标题或摘要，不视为已验证具体规则。
2. **是否匹配场景**：终端、版本、账号/权限、功能模块是否适用。
3. **来源是否可靠**：已确认的产品规则与正式状态优先；历史咨询案例只能作为排查线索。
4. **是否互相冲突**：若规则矛盾，核对更新时间、版本和适用范围；仍无法判断则明确说明存在冲突。
5. **有没有直接回答用户的证据**：未检索到 ≠ 功能不存在；案例命中 ≠ 当前故障已确诊。

### 第 4 步：形成检索结论

把检索结果交还主 Agent，用于生成回答：

- `结论`：可确认 / 仅有排查线索 / 资料不足 / 资料冲突。
- `事实依据`：可支持回答的具体规则或步骤。
- `适用范围`：终端、版本、角色等；未知则标明。
- `来源`：真实读取到的文件链接或业务文档标识。
- `下一步`：直接回答 / 提出一个关键问题 / 根据已知排查路径继续 / 告知无法确认。

内部可以按以上字段思考，不要求向用户展示生硬的检索报告或置信度数字。用户需要时，附简短可核对的来源。

## 异常和限制

- **工具不可用**：不声称“查过知识库”；提示当前没有相应检索能力。
- **查无结果**：只说“当前资料中无法确认”，不要推断产品不支持。
- **只有旧案例**：用作建议方向，明确尚需用户验证。
- **可能涉及风险的操作**：不因历史案例提过就直接建议清除数据、重装、绕过权限。
- **来源中存在用户内容或机密**：不对外输出其他员工的聊天原文、账号标识或凭据。
- **模拟资料**：严格限制在演示/测试语境。

## 与其他模块协作

- `agent.md`：决定是否检索、是否追问与何时结束。
- `faq-support`（计划中）：利用确认的产品资料解释使用方法。
- `issue-support`（计划中）：利用规则与案例进行多轮诊断。
- KMS、表格、GitHub、OpenViking：属于**外部数据来源/工具**，不是本 Skill 自带的能力。

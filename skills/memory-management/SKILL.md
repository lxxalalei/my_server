# 记忆沉淀与维护

负责把可复用的处理结果和更正交给记忆系统，并维护已存在的记忆。普通查资料使用检索能力，不必先执行记忆维护。维护时可读取目标记忆以核对内容和范围。

按实际接入的 OpenViking 版本、记忆策略、身份作用域及接口执行，不另建本地记忆文件、候选案例库或人工审核状态机。

## 沉淀

自动沉淀是默认行为，无需用户或产品经理逐次说“记住”。将会话与处理结果通过既有接入机制交给 OpenViking，按实际策略提交，由其执行记忆提取、合并和更新。已自动捕获、提交的内容不再逐条重复写入；具体触发时机遵循接入配置。

重点保留可复用的解答、有效处理办法、人工更正、需求分析结论与产品决定，以及继续处理所需的背景。保留来源、时间、已知版本、适用条件和确认情况；区分用户事实、分析估算、建议和产品经理决定。用户确认某方法有效不代表根因已查明。

当前任务已确认有效更正后，将新结论及其纠正的旧判断一并交给记忆流程，保留来源、确认情况与适用范围，让后续召回能识别过时信息。结论仍有冲突时保留待确认状态，不通过写入记忆把猜测变成事实。按 OpenViking 策略维护记忆，不自动改写产品文档或业务记录。

未解决事项可以保留为上下文，不能标成已验证经验。记录必要事实与简要依据，不保存完整内部推演、凭据或无关私人信息。

用户明确要求记住某事，或实际策略允许且需要提前持久化时，使用可用的显式记忆接口；普通会话的自动沉淀仍按 OpenViking 策略处理。

## 核对结果

会话提交被接受不等于长期记忆已经更新；依赖更新结果前检查实际完成情况。记忆提取也可能不产生变更，不能承诺每段会话都会形成新记忆。

显式更正或遗忘时，按实际记忆 URI 核对目标与范围，不根据模糊匹配删除。授权、执行结果核查和失败反馈遵循总指令；记忆更新通过 OpenViking 实际接口完成，不用本地文件替代。

实现语义参考 OpenViking 官方的[会话机制](https://github.com/volcengine/OpenViking/blob/main/docs/en/concepts/08-session.md)与[记忆使用指引](https://github.com/volcengine/OpenViking/blob/main/examples/skills/openviking-memory/SKILL.md)，具体能力以部署版本为准。

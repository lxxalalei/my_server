# FAQ Support｜产品使用咨询 v0.1

## 目标

让员工快速知道**如何完成目标、需要满足什么条件、为什么找不到某项操作**。不要为了“完成一次 FAQ”而忽略用户实际遇到的困难。

本 Skill 负责**使用咨询的组织与解答**；知识如何检索与校验，交给 `knowledge-search`；对话调度与问题是否结束，交给 `agent.md`。

## 适用情形

- “如何创建群聊？”“在哪里修改群名称？”
- “普通成员能修改群名称吗？”
- “这个功能是否支持？”“需要什么权限？”
- 用户描述“找不到入口”，可能是不了解操作，也可能是使用异常。

不要要求用户选择 FAQ 类别；主 Agent 可自行采用本方法，并根据反馈切换处理方向。

## 处理流程

### 1. 明确目标和上下文

从用户已有表述获取目标、客户端、账号角色/权限、已尝试路径。**不要重复问已提供的信息**。

若平台或角色会直接改变步骤，而且缺失信息妨碍继续，可以先问**一个**关键问题；否则先检索并给出当前能确认的通用信息。

### 2. 核对产品知识

产品专属的入口、按钮名称、权限、支持范围、版本差异等事实，使用 `knowledge-search` 读取匹配的知识正文。

特别注意：
- “没有找到某功能的文档”不等于“该功能不存在”。
- 历史咨询只可辅助理解问题，不应覆盖已确认的正式产品规则。
- 若同一功能在 Windows / Android / iOS 的操作不同，只提供适用于当前终端的步骤；不知道终端又无法确定步骤时再问。
- 在当前公开模拟知识仓库中，只能以“演示版 / DEMO”的口径回答，不能将模拟规则冒充真实火星规则。

### 3. 给出可执行回答

优先按实际情况组织，无需固定话术模板：

- **操作咨询**：直接给出入口、必要操作步骤和影响成功的前置条件。
- **规则/权限咨询**：先回答能否、对谁适用、何时适用；依据不足时明确无法确认。
- **找不到入口**：先核对是否符合已知权限和适用平台；若符合仍无法操作，转到异常排查。
- **不支持与新增需求**：只有资料明确支持“不支持”的结论才能这么说；否则只说明现有资料无法确认。用户提出建议时可以作简要回应，不声称已记录或提交。

回答应具体但简短；已能直接解决时不额外增加“您使用哪个版本、哪个账号”等无意义追问。

### 4. 处理后续反馈

- 用户照步骤完成：可以结束当前问题，不继续索取信息。
- 用户说“没有这个按钮”“点了没有反应”“提示错误”：保留已知上下文，转用 `issue-support` 的排查方法。
- 用户提出新目标：重新理解诉求，必要时再检索。
- 用户问题仍未解决：说明下一步要查的关键事实，或提供当前真实可用的人工处理路径；不要编造解决状态。

## 示例（仅用于模拟测试）

**员工：** 演示版普通群成员怎么修改群名称？

**检索依据：** `lxxalalei/knowledge/product/group-chat.md` 正文说明：模拟版仅群主、管理员有修改权限。

**合格回答：** “按目前演示版的规则，普通成员不能修改群名称，只有群主或管理员可以。具有权限的成员可进入群聊的‘群设置 → 群名称’操作。你可以请群主或管理员协助修改。”

**后续：** 如果员工表示自己就是管理员但依然看不到入口，不能再重复“只有管理员能修改”，应转异常排查并核对终端与界面现象。

## 质量检查

- 是否真正依据已读取的资料回答产品事实？
- 是否直接解决用户要做的事，而非罗列概念？
- 是否正确考虑权限、终端、版本等适用条件？
- 是否在证据不足时避免编造“支持/不支持”？
- 是否在实际异常出现时及时切换处理路径？
